# Источники и режим «Дополнение»

## Источники

Поддерживаются четыре типа источников. Любой из них допустим как единственный вход; несколько источников объединяются через режим «Дополнение».

| Источник | Как читать | Что извлекать |
|---|---|---|
| Документация (md, docx, pdf, экспорт Confluence, BPMN/UML, User Story, требования) | Прочитать содержимое | Функционал, экраны, элементы, роли; BPMN/UML — как описание процесса |
| Скриншот страницы/модального окна | Изображение | Все интерактивные элементы и их логические группы |
| URL / живой ресурс (HTML) | HTTP-fetch страницы | Интерактивные элементы по тегам/атрибутам |
| Figma (MCP, REST API или встроенный браузер Orca) | MCP/REST — чтение фреймов и узлов; браузер — визуальное чтение экранов | Фреймы, слои, тексты, компоненты выбранного фрейма |

### Правила чтения скриншота / HTML

- Выделяй все **интерактивные** элементы (кнопки, ссылки, поля, чекбоксы, радиокнопки, выпадающие списки, переключатели) и их логические группы (контейнеры, секции, списки).
- Строй иерархию вложенности: список содержит элементы, форма — поля и кнопки, панель — секции.
- Игнорируй чисто информационные статические тексты/заголовки/подсказки, **кроме** метки поля — метка считается частью поля.
- Информационные блоки не должны иметь дочерних элементов.
- Для HTML ориентиры: теги `button, a, input, select, textarea, checkbox, radio`; атрибуты `role, onclick`; контейнеры `div, section, form, ul, ol, li, table`.
- Для каждого элемента указывай: название, тип (контейнер, кнопка, ссылка, поле ввода, чекбокс, список, секция, информационный блок), действие (если интерактивен), дочерние блоки (для контейнеров).

### Правила чтения Figma

- Читай фреймы, узлы, слои, тексты и компоненты выбранного фрейма/страницы.
- Дерево слоёв/компонентов маппь на контейнеры `(+)` и конечные элементы по канону.
- Скрытые и служебные слои отсекай.
- При отсутствии Figma MCP сначала проверь Figma REST API (если есть токен), иначе читай макет через встроенный браузер Orca — порядок шагов и команды в `figma-access.md`. О недоступности Figma сообщай только если недоступны все способы.

### Нормализация

Любой источник приводится к единому канону (`hierarchy-canon.md`): табуляция + дефисы, `(+)` для контейнеров, «Отображение …», роли по порогу ≥ 70 %, исключения (валидации/ошибки/API/backend/сценарии/тест-кейсы).

## Снимки источников

Сохраняй снимки входов в `.scratch/<feature-slug>/decomposition/sources/` (например, `docs.md`, `page.html`, `screenshot-1.png`, `figma-<file-key>.md`). Это позволяет воспроизвести декомпозицию и объяснить провенанс.

## Режим «Дополнение»

Запускается, когда `hierarchy.md` уже существует и появился новый источник. Цель: проанализировать, чего нельзя было выделить из предыдущих источников и теперь можно, и **дополнить** декомпозицию, а не пересобрать её.

Алгоритм:

1. **Сопоставить.** Для нового источника определить функционал, который в нём виден, и сверить с текущим деревом.
2. **Классифицировать** каждый элемент: `уже есть` / `нет в дереве` / `противоречит`.
3. **Добавить только недостающее** — на корректную глубину, с соблюдением канона формата и нейминга.
4. **Не трогать существующее.** Никаких переименований, удалений, перемещений и «улучшений» без явного подтверждения пользователя.
5. **Зафиксировать провенанс** каждого добавленного узла (источник, дата).
6. **Составить отчёт** и записать в `provenance.md`.

Правила:

- Если новый источник ничего не добавляет — сообщи «пробелы не найдены» и не меняй дерево.
- Если элемент противоречит существующему — оформи конфликт в отчёте, дерево не меняй, спроси пользователя.
- Изменения формата существующих узлов (например, чтобы привести к канону) вноси только явно и отдельным списком «нормализовано».

### Пример отчёта «Дополнения»

```text
## Дополнение от 2026-10-12, источник: Figma «Настройки виджета»
Добавлено (3):
	-Опция настройки виджета (+) → --Отображение переключателя "Тихий режим".
	-Опция настройки виджета (+) → --Отображение подсказки "Изменения сохранятся автоматически".
	-Опция поиска. (+) → --Отображение истории поиска (+)
Не изменено: 27 узлов.
Конфликты (0): —
```

## Чек-лист этапа «Источники / Дополнение»

- [ ] Все заявленные источники обработаны (или явно помечены как недоступные).
- [ ] Снимки источников сохранены.
- [ ] Результат приведён к единому канону иерархии.
- [ ] В режиме «Дополнение» существующие узлы не изменены без подтверждения.
- [ ] Отчёт `добавлено / не изменено / конфликты` составлен; провенанс зафиксирован.
