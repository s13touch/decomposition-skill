# XML-схема draw.io

Генерация `hierarchy.drawio` из готовой иерархии. Роль — эксперт по генерации XML для draw.io: ты **не** анализируешь документацию, **не** декомпозируешь и **не** меняешь дерево.

## Входные данные

1. XML-шаблон draw.io (см. `examples/drawio-template.xml`).
2. XML-пример draw.io.
3. **Готовая иерархия функционала** (markdown tree, табуляция + дефисы, `(+)`).
4. При необходимости — изображение ожидаемой схемы.

Единственный источник истины — предоставленная иерархия.

## Каркас файла

```xml
<mxGraphModel dx="1272" dy="938" grid="1" gridSize="10" guides="1" tooltips="1"
              connect="1" arrows="1" fold="1" page="1" pageScale="1"
              pageWidth="827" pageHeight="1169" math="0" shadow="0">
  <root>
    <mxCell id="0" />
    <mxCell id="1" parent="0" />
    <!-- swimlane верхнего уровня и их содержимое -->
  </root>
</mxGraphModel>
```

- `<mxCell id="0" />` и `<mxCell id="1" parent="0" />` — обязательны и неизменны.
- Каждый swimlane верхнего уровня крепится к `parent="1"`.
- Содержимое swimlane (события, шлюзы, задачи, рёбра) — `parent="<id swimlane>"`.
- У вершин `vertex="1"`, у связей `edge="1"`; у каждой ячейки обязательны `id`, `parent`, `style`, `value`, геометрия в `<mxGeometry ... as="geometry">`.
- У рёбер обязательны `source`, `target` и якоря подключения `exitX=1;exitY=0.5` / `entryX=0;entryY=0.5` (см. «Ребро (связь)»); геометрия `<mxGeometry relative="1" as="geometry">`.
- Swimlane содержит `<mxRectangle ... as="alternateBounds" />` внутри `mxGeometry`.

## Стили (копировать 1:1, менять нельзя)

**Swimlane (контейнер):**
```
swimlane;html=1;startSize=28;horizontal=0;fillColor=#FFFFFF;swimlaneFillColor=none;
```

**Стартовое событие (зелёное):**
```
points=[[0.145,0.145,0],[0.5,0,0],[0.855,0.145,0],[1,0.5,0],[0.855,0.855,0],[0.5,1,0],[0.145,0.855,0],[0,0.5,0]];shape=mxgraph.bpmn.event;html=1;verticalLabelPosition=bottom;labelBackgroundColor=#ffffff;verticalAlign=top;align=center;perimeter=ellipsePerimeter;outlineConnect=0;aspect=fixed;outline=standard;symbol=general;fillColor=#FFFFFF;strokeColor=#97D077;
```

**Конечное событие (красное, terminate):**
```
points=[[0.145,0.145,0],[0.5,0,0],[0.855,0.145,0],[1,0.5,0],[0.855,0.855,0],[0.5,1,0],[0.145,0.855,0],[0,0.5,0]];shape=mxgraph.bpmn.event;html=1;verticalLabelPosition=bottom;labelBackgroundColor=#ffffff;verticalAlign=top;align=center;perimeter=ellipsePerimeter;outlineConnect=0;aspect=fixed;outline=end;symbol=terminate2;fillColor=#FFFFFF;strokeColor=#FF6666;
```

**Шлюз (exclusive gateway):**
```
points=[[0.25,0.25,0],[0.5,0,0],[0.75,0.25,0],[1,0.5,0],[0.75,0.75,0],[0.5,1,0],[0.25,0.75,0],[0,0.5,0]];shape=mxgraph.bpmn.gateway2;html=1;verticalLabelPosition=bottom;labelBackgroundColor=#ffffff;verticalAlign=top;align=center;perimeter=rhombusPerimeter;outlineConnect=0;outline=none;symbol=none;gwType=exclusive;fillColor=#FFFFFF;
```

**Задача / блок (BPMN task):**
```
points=[[0.25,0,0],[0.5,0,0],[0.75,0,0],[1,0.25,0],[1,0.5,0],[1,0.75,0],[0.75,1,0],[0.5,1,0],[0.25,1,0],[0,0.75,0],[0,0.5,0],[0,0.25,0]];shape=mxgraph.bpmn.task;whiteSpace=wrap;rectStyle=rounded;size=10;taskMarker=abstract;isLoopSub=0;strokeColor=#7EA6E0;fontSize=10;
```

**Ребро (связь):**
```
edgeStyle=orthogonalEdgeStyle;rounded=0;orthogonalLoop=1;jettySize=auto;html=1;exitX=1;exitY=0.5;exitDx=0;exitDy=0;exitPerimeter=0;entryX=0;entryY=0.5;entryDx=0;entryDy=0;entryPerimeter=0;
```

**Точки подключения (обязательны для всех рёбер).** `exitX=1;exitY=0.5` — выход из середины правой грани, `entryX=0;entryY=0.5` — вход в середину левой грани. Без этих атрибутов draw.io выбирает ближайшую грань; у блоков, стоящих вертикальным стеком, это верх/низ, и стрелка «ныряет» в блок сверху вместо подключения сбоку. Полагаться на авто-выбор грани **запрещено**.

- `isLoopSub=1` — контейнер (элемент с `(+)`), раскрывается в отдельную схему.
- `isLoopSub=0` — конечный элемент (без `(+)`).
- Значения `value` у событий и шлюзов — пустые (`value=""`); у задач и swimlane — имя элемента.

## Строение схемы

- Каждый **раздел верхнего уровня** и каждый элемент `(+)` → **отдельный swimlane**.
- Вложенные по смыслу контейнеры — это **sibling-swimlane с `parent="1"`**, а НЕ swimlane внутри swimlane; разноси их по абсолютным координатам.
- Внутри каждого контейнера — полный каркас: стартовое событие → шлюз → цепочка задач (в порядке дерева) → шлюз → конечное событие.
- Элемент без `(+)` — обычный BPMN-task-блок внутри родителя.
- Порядок элементов строго как в дереве.
- Связи — только `родитель → дочерний элемент`, дополнительных переходов нет.

## Правила генерации

1. Элемент с `(+)` → отдельный контейнер (swimlane) с возможностью перехода на следующий уровень.
2. Элемент без `(+)` → конечный блок, дочерних схем нет.
3. Каждый раздел верхнего уровня → отдельная диаграмма (отдельный swimlane верхнего уровня).
4. Родитель → контейнер; его дети → дочерние элементы внутри.
5. Порядок элементов — строго как в дереве.
6. Связи — только «родитель → дочерний элемент».
7. У каждого ребра явно заданы якоря `exitX=1;exitY=0.5` и `entryX=0;entryY=0.5` (подключение справа → слева). Авто-выбор грани не допускается.
8. Стиль полностью копируется из шаблона (цвета, рамки, типы фигур, шрифты, BPMN) — не менять.
9. Размеры контейнеров могут расти под детей; размеры блоков можно править только против наложения текста.
10. Координаты рассчитываются автоматически: нет пересечений, читаемость, равные интервалы, единый стиль. (Точная расстановка — см. `layout.md`.)
11. Каждый `mxCell` имеет **уникальный `id`**; повторение запрещено. `id="0"`/`id="1"` зарезервированы.

## Экранирование

- `<` → `&lt;`, `>` → `&gt;`, `"` → `&quot;`, `&` → `&amp;`.
- Текст подписи пишется в атрибут `value="..."`.
- Допустима HTML-обёртка: `<div>…</div>` или `<font style="font-size: 8px;">…</font>`.

## Запрещается

- Менять структуру дерева, переименовывать, объединять, разбивать, добавлять, удалять, переставлять, «исправлять» дерево.
- Делать выводы на основе документации.
- Любое отклонение от предоставленной структуры.

## Формат ответа

**Только XML.** Без Markdown, без комментариев, без пояснений.
