# Расстановка блоков схемы

Логическая расстановка уже созданных swimlane-контейнеров на плоскости, чтобы вложенность parent→child читалась визуально. Промпт **меняет только координаты** блоков.

Роль — эксперт по расстановке swimlane. Иерархия и набор блоков — единственный источник истины: не анализируй документацию, не декомпозируй, не меняй состав/имена блоков и внутреннюю BPMN-структуру.

## Что расставляется

- Расставляются **только контейнеры `(+)`** — каждый это отдельный swimlane.
- Листья (без `(+)`) — BPMN-задачи **внутри** родителя; отдельный swimlane для них не создаётся и в расстановке они не участвуют.
- Глубина считается **только по цепочке контейнеров**: корневые контейнеры = `depth 0`, дочерний = `depth(родителя) + 1`.

## Главное правило: чередование направления

Направление детей-контейнеров зависит от чётности глубины родителя:

| Глубина родителя | Куда дети-контейнеры | Выравнивание |
|---|---|---|
| чётная (0, 2, 4…) | **ВПРАВО** (горизонтальный ряд) | верхняя граница детей = `y` родителя |
| нечётная (1, 3, 5…) | **ВНИЗ** (вертикальный столбец) | левая граница детей = `x` родителя |

## Ключевой нюанс соседей

Следующий sibling сдвигается не на `SWIM_W + H_GAP`, а по **bbox поддерева** предыдущего:

- по горизонтали: `previous_sibling.subtree.right + H_GAP`;
- по вертикали: `previous_sibling.subtree.bottom + V_GAP`.

Иначе глубокая ветка наедет на следующего соседа.

## Константы и размеры

- `SWIM_W = 480`, `H_GAP = 40`, `V_GAP = 40`.
- Высота: `H = max(160, 10 + (N-1)*70 + 62.5 + 20)`, где `N` — число прямых детей (и листья, и контейнеры).
- Ширина swimlane фиксирована — 480.
- Координаты внутренних task (`x = 195`, вертикальный стек) не менять.

## Алгоритм

```text
Шаг 0. Построить дерево только из контейнеров (+). Родитель = ближайший контейнер выше.
        Порядок детей = порядок появления в иерархии. Не сортировать.
Шаг 1. Корни (depth=0): x0=40, y=40; для каждого root: layout(root, x, y, 0);
        y = root.subtree.bottom + V_GAP
Шаг 2. layout(node, x, y, depth):
        place node (x, y); kids = прямые дети-контейнеры (+)
        если kids пуст: right = x + SWIM_W; bottom = y + H; return
        если depth % 2 == 0 (вправо):
            cx = x + SWIM_W + H_GAP; cy = y
            для child: layout(child, cx, cy, depth+1); cx = child.subtree.right + H_GAP
        иначе (вниз):
            cx = x; cy = y + H(node) + V_GAP
            для child: layout(child, cx, cy, depth+1); cy = child.subtree.bottom + V_GAP
        node.right  = max(x + SWIM_W, max child.right)
        node.bottom = max(y + H,       max child.bottom)
```

## Примеры (обязательная логика)

- A. `Закрытый виджет (+)` → дети `Отображение логотипа (+)`, `Отображение счётчика… (+)` идут **вправо**, одним рядом (тот же `y`).
- B. `Открытый виджет (+)` → `Опция настройки виджета (+)` вправо; её ребёнок `Открытие модального окна (+)` (depth 1) — **вниз**.
- C. На нечётной глубине несколько детей — столбец друг под другом с тем же `x`.
- D. depth 2 → снова вправо; depth 3 → вниз (чередование).
- E. `Список чатов` начинается правее **всего subtree** `Опция поиска`, а не только самого блока.
- F. Несколько корней — один левый столбец, каждый ниже всего subtree предыдущего.

## Что НЕ является правильной расстановкой

- Колонки строго по глубине (все depth=0 в колонке A и т. д.), если теряется «ребёнок справа/снизу от родителя».
- Сдвиг соседа только на ширину одного блока.
- Произвольный «красивый» grid вопреки parent→child геометрии.
- Склейка одинаковых по имени блоков из разных веток в одну позицию (это разные swimlane с разными координатами).

## Формат выхода

- Файл draw.io (предпочтительно native `.drawio`, при проблемах — plain/uncompressed).
- Без Markdown-обёртки вокруг XML, без комментариев в XML, без пояснений.
- При создании нового файла не перезаписывай исходник — сохраняй отдельно (например, `Схема. <фича> (расстановка).drawio`).

## Чек-лист перед выдачей

- [ ] Число swimlane = числу элементов `(+)`.
- [ ] Никто не переименован и не потерян.
- [ ] Порядок детей сохранён (как в иерархии).
- [ ] У чётных родителей дети с `y ≈ y_родителя` и `x > x_родителя`.
- [ ] У нечётных родителей дети с `x ≈ x_родителя` и `y > y_родителя + H`.
- [ ] Нет пересечений с учётом gap'ов.
- [ ] Сдвиг sibling учитывает subtree (bbox).
- [ ] Следующий root ниже `subtree.bottom` предыдущего.
- [ ] Файл открывается в draw.io без ошибки XML.
