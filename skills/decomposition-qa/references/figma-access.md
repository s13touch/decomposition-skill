# Доступ к Figma (без Figma MCP)

Как читать макет Figma, если у агента **нет Figma MCP**, а макет открыт во встроенном браузере Orca.

Справочник-«тропа»: по нему агент проходит путь без повторного исследования граблей.

## Когда применять

- Источник декомпозиции — Figma, а Figma MCP не подключён.
- Пользователь говорит «экраны открыты в соседнем окне», даёт `figma.com/design/...` или `figma.com/file/...`.
- Нужны фреймы, экраны, элементы и состояния макета для `hierarchy.md`.

## Порядок выбора способа доступа

Проверяй сверху вниз, бери первый доступный:

| Способ | Когда | Что даёт |
|---|---|---|
| 1. Figma MCP | есть в списке MCP-ресурсов | дерево слоёв/нод (идеально) |
| 2. Figma REST API | есть personal access token (`FIGMA_TOKEN`/`FIGMA_PAT`) | JSON-дерево `/v1/files/:key/nodes?ids=…`, рендер `/v1/images/:key` |
| 3. **Встроенный браузер Orca** | макет открыт в Orca | визуальное чтение: зум + панорама + скриншоты (этот справочник) |
| 4. Внешний браузер | макет в Chrome/Safari | только через Computer Use / Playwright, Orca-команды не работают |

Если доступен способ 1 или 2 — используй его, способ 3 в 5–10 раз дороже по времени.
Ключ файла берётся из URL: `figma.com/design/<FILE_KEY>/<название>?node-id=...`.

## Что НЕ работает (проверено)

- **`/api/files/<key>` через cookies** — отдаёт только meta файла (имя, thumbnail, link_access). Дерева нод там нет.
- **`/api/files/<key>/nodes?ids=…`** — 404. Документ грузится по WebSocket, HTTP-эндпоинта с деревом нет.
- **DOM/a11y-снимок (`orca snapshot`)** — у Figma канвас WebGL: в снапшоте только тулбар/меню (кнопки «Zoom to fit», «Hand tool» и т. п.), содержимое макета не читается.
- **Выделение слоёв** — при `link_access: view` (просмотр без логина) выделение и панель Pages/Layers недоступны.
- **`set viewport` для увеличения картинки** — при оверрайде больше физической поверхности рендер начинает **тайлиться** (одна и та же картинка повторяется сеткой). Не использовать.
- **Drag по канвасу** инструментом Move — открывает модалку «Sign up for Figma». Не тянуть; при необходимости панорамы пользоваться `pan`.

## Главные факты геометрии (запомнить)

1. Размер PNG = `innerWidth × devicePixelRatio` по ширине и `innerHeight × devicePixelRatio` по высоте.
2. **CSS-координаты для `zoom`/`pan` = пиксели скриншота ÷ `devicePixelRatio`.**
   Пример: снимок `1189×878`, `dpr = 1.25` → CSS-вьюпорт `951×702`.
3. Всегда начинай с `geom` — размер поверхности у Orca-вкладки меняется от запуска к запуску.
4. Зум привязан к **реальной позиции курсора**. Поэтому: зум в точке `A` оставляет `A` на месте, а точка `P` уезжает в `A + (P − A) · (z₂/z₁)`.
5. Один синтетический wheel-ион панорамирует заметно сильнее, чем `deltaY` (наблюдалось ≈ ×1.5 в CSS-px). Панораму либо калибруй один раз по двум скриншотам, либо не используй вовсе (см. приём с якорем ниже).

## Пошаговый алгоритм

### Шаг 0. Найти вкладку и реальную геометрию

```bash
node scripts/orca-figma.mjs tabs
node scripts/orca-figma.mjs geom
```

Нужна вкладка с `figma.com/...` и её `browserPageId`. Для параллельной работы передавай `--page <id>`.

### Шаг 1. Зафиксировать канонический вид

Перезагрузка/goto **не** сбрасывает вид: Figma восстанавливает позицию из сессии. Единственные надёжные способы вернуться в начало — `Zoom to fit` или новая вкладка.

```bash
node scripts/orca-figma.mjs fit
node scripts/orca-figma.mjs shot sources/00-fit.png
```

`fit` жмёт кнопку зума и пункт «Zoom to fit» из меню (ищутся по имени в снапшоте, поэтому refs не хардкодятся).

### Шаг 2. Измерить координаты кадров

Открой `00-fit.png` как изображение. На 5 % видно все фреймы. Для каждого фрейма возьми центр его рамки в пикселях картинки и переведи в CSS:

```
CSS_x = px_x / dpr ,  CSS_y = px_y / dpr
```

### Шаг 3. Зум на нужный кадр

```bash
node scripts/orca-figma.mjs zoom <CSS_x> <CSS_y> <ticks>
```

- `ticks` — сколько шагов колеса; в этой сборке ≈ ×1.16 за шаг: `ticks ≈ ln(цель/5%) / ln(1.16)`.
  Ориентиры: 15 шагов → ≈45 %, 21 шаг → ≈120 %.
- **`zoom` сам делает `mouse move` в ту же точку** — без этого Figma отзумит от старого курсора и кадр уедет (главная грабля).
- Рабочая точка чтения: 45 % для десктопного экрана 1440 px (текст 12 px ≈ 6–7 физ. пикселей — читается).
  Для плотных таблиц/мелких подписей — 90–120 % и несколько снимков с панорамой.

### Шаг 4. Приём с якорем (вместо панорамы)

Если кадр «уезжает» вниз за экран, не панорамируй — выбери якорь по формуле. Хочется, чтобы центр кадра попал в `T` (например, `y ≈ 335` — середина видимой области):

```
якорь_y = T + (C_fit − T) / (z₂/z₁ − 1)
```

где `C_fit` — центр кадра в CSS на шаге «fit», `z₂/z₁` — во сколько раз увеличиваешь. Проще подобрать один раз экспериментально: якорь **ниже** центра кадра подтягивает кадр вверх, **выше** — опускает.

### Шаг 5. Снять и прочитать

```bash
node scripts/orca-figma.mjs shot sources/<кадр>-01.png
```

Читай PNG как изображение. Широкий фрейм (2–4 экрана) требует нескольких снимков: ширина одного десктопного экрана на 45 % ≈ 650 CSS, вьюпорт ≈ 950 CSS → ~1.4 экрана за снимок.

### Шаг 6. Детализация спорных мест

Точечно зумируй на область (шапка, вкладки, заголовок пустого состояния, дропдаун) по той же схеме: `fit → zoom → shot`.
Считай положение цели в CSS из уже снятого кадра той же формулой `A + (P′ − A)/9` (для зума ×9 от 5 %), не забывая про сделанную панораму.

## Низкоуровневые команды (если скрипт недоступен)

Всё то же самое руками через `orca`:

```bash
orca tab list --json
orca exec --command "mouse move 390 188"          # обязательно перед зумом
orca eval --expression "(function(){var x=390,y=188,n=15;var t=document.elementFromPoint(x,y)||document.body;for(var i=0;i<n;i++){t.dispatchEvent(new WheelEvent('wheel',{deltaY:120,deltaMode:0,ctrlKey:true,clientX:x,clientY:y,bubbles:true,cancelable:true,view:window}));}return 'ok';})()"
orca exec --command "mouse move 475 350"
orca eval --expression "(function(){var x=475,y=350;var t=document.elementFromPoint(x,y)||document.body;t.dispatchEvent(new WheelEvent('wheel',{deltaX:0,deltaY:60,deltaMode:0,ctrlKey:false,clientX:x,clientY:y,bubbles:true,cancelable:true,view:window}));return 'ok';})()"
orca screenshot --json > shot.json                # base64 → декодировать в .png
orca exec --command "set viewport 1575 878 1"     # НЕ использовать: тайлинг
```

Полезные agent-browser команды (через `orca exec --command "..."`): `mouse move/down/up`, `mouse wheel --dy`, `press`, `keydown`, `inserttext`, `set device`, `set media`, `clipboard read/write`.

## Грабли

| Симптом | Причина | Решение |
|---|---|---|
| После зума пустой канвас | зум привязан к реальному курсору; он стоял в пустой области | перед зуомом `mouse move` в точку внутри кадра |
| `goto`/reload не возвращает в исходный вид | Figma восстанавливает вид сессии | `Zoom to fit` или новая вкладка |
| Картинка повторяется сеткой | `set viewport` больше физической поверхности | не оверрайдить viewport |
| `runtime_unavailable` | Orca-рантайм транзиентно рвёт соединение | повторить команду 3–8 раз (в скрипте уже есть) |
| `@e6` перестал работать | refs живут до навигации/переключения вкладки | заново `snapshot` |
| Открылась модалка «Sign up for Figma» | drag по канвасу в режиме просмотра | `press Escape`; не драгать |
| Панорама «прыгает» сильно | wheel-панорама идёт с множителем | калибровка или приём с якорем |
| Не видно нижней части экрана | панель «Sign up to comment…» перекрывает ~120 CSS снизу | держать центр кадра на `y ≈ 335` |
