# Конвейер, артефакты и оркестрация

## Схема конвейера

```
Источники ──► [0] Сбор контекста
                    │
                    ▼
             [1] Иерархия (markdown tree) ──► hierarchy.md
                    │
       ┌────────────┼─────────────────────────┐
       ▼            ▼                         ▼
 [2] XML-схема  [3] Расстановка        [4] Матрица покрытия
  hierarchy.drawio (координаты)            matrix.xlsx
       │
       └── [C] Дополнение (при новом источнике) ── переиспользует [1] и производные
```

Иерархия — единственный источник истины. Этапы 2–4 независимы друг от друга и зависят только от `hierarchy.md`.

## Этапы

| Этап | Вход | Выход | Справочник |
|------|------|-------|-----------|
| 0. Контекст | любые источники | снимки в `sources/` | `inputs-and-augmentation.md` |
| 1. Иерархия | источники | `hierarchy.md` | `hierarchy-canon.md`, `inputs-and-augmentation.md` |
| C. Дополнение | `hierarchy.md` + новый источник | обновлённый `hierarchy.md` + `provenance.md` | `inputs-and-augmentation.md` |
| 2. XML-схема draw.io | `hierarchy.md` | `hierarchy.drawio` | `xml-schema-drawio.md` |
| 3. Расстановка | `.drawio`/иерархия | `.drawio` с координатами | `layout.md` |
| 4. Матрица покрытия | `hierarchy.md` | `matrix.xlsx` | `coverage-matrix.md` |

## Порядок запуска

Скилл работает **по шагам** (см. `checkpoints.md`): один этап за ход, после каждого остановка и подтверждение.

- Полный конвейер выполняется последовательно: 0 → 1 → (шлюз: подтверждение иерархии) → (C при необходимости) → 2 → 3 → 4, с остановкой на каждом шлюзе.
- Отдельные этапы: любой этап 2–4 можно запустить отдельно, если `hierarchy.md` уже существует **и подтверждён**.
- Если схема генерируется с нуля, этап 3 выполняется сразу после этапа 2 (со своим шлюзом).
- Никогда не запускай весь конвейер за один проход.

## Точки контроля

После каждого этапа скилл **останавливается** и выводит результат его чек-листа (см. `checkpoints.md`). Правила:

- Альтернативы нет: один этап за ход, затем ожидание подтверждения.
- Обязательный шлюз после иерархии: список → правки/подтверждение → только потом дальше.
- Чек-лист не пройден → остановиться, показать, что именно не так, спросить пользователя.
- Не «додумывать» недостающие элементы и не додумывать формат.
- Не менять уже согласованные узлы без явного подтверждения.

## Раскладка артефактов

```
.scratch/<feature-slug>/
  spec.md
  decomposition/
    hierarchy.md      # каноническое дерево
    hierarchy.drawio  # XML-схема после расстановки
    matrix.xlsx       # матрица покрытия
    provenance.md     # провенанс узлов + журнал «Дополнения»
    sources/          # снимки входных источников
```

Правила хранения:

- Исходные файлы (документы, снимки, макеты) не перезаписываются.
- При генерации нового `.drawio` не перезаписывай исходный файл — сохраняй отдельно (например, `Схема. <фича> (расстановка).drawio`).
- `provenance.md` — sidecar: форматы XML и XLSX он не ломает.

## Провенанс

Для каждого узла дерева желательно хранить источник (документация / скриншот / URL / Figma) и дату добавления. Формат — раздел `provenance.md`, например:

```text
## Провенанс узлов
- «Открытый виджет (+)» — документация (Confluence), 2026-10-12
- «Опция поиска. (+)» — Figma «Настройки виджета», 2026-10-12
```
