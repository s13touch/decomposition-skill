# Декомпозиция функционала (decomposition-qa)

Превращает любой доступный источник (документацию, скриншот, живой URL, макет Figma) в каноническую иерархическую декомпозицию функционала проекта и её QA-артефакты:

1. `hierarchy.md` — каноническое markdown-дерево (**единственный источник истины**)
2. `hierarchy.drawio` — XML-схема draw.io, построенная из дерева
3. логическая расстановка блоков схемы
4. `matrix.xlsx` — табличная матрица покрытия

Декомпозиция строго **структурная**: в неё никогда не попадают валидации, ошибки, API/backend, SQL, алгоритмы, события, сценарии и тест-кейсы.

## Когда применять

- Пользователь даёт документацию, скриншот, URL или ссылку на Figma и хочет разобрать функционал на составляющие.
- Нужно дополнить существующую декомпозицию новым источником (режим «Дополнение»).
- Нужна визуальная схема покрытия в draw.io или матрица покрытия в XLSX.

## Перед началом

Прочитай справочники — это контракт, а не рекомендации:

- `references/pipeline.md` — этапы, раскладка артефактов, оркестрация.
- `references/hierarchy-canon.md` — единственно допустимый формат дерева, нейминг, роли, исключения.
- `references/inputs-and-augmentation.md` — как читать каждый источник и как **дополнять** уже собранное дерево.
- `references/xml-schema-drawio.md` — шаблон draw.io и правила генерации.
- `references/layout.md` — алгоритм расстановки.
- `references/coverage-matrix.md` — спецификация XLSX-матрицы.

## Процесс

### 0. Собрать контекст

Зафиксируй `feature-slug` и все доступные источники. Сохрани снимки входов в `.scratch/<feature-slug>/decomposition/sources/`. Если источник недоступен (нет Figma MCP, нет доступа к ресурсу) — сообщи, какие источники реально доступны, и продолжай с остальными. Не выдумывай элементы.

### 1. Построить иерархию

Разбери источники по правилам `references/inputs-and-augmentation.md` и собери дерево строго по канону `references/hierarchy-canon.md`. Запиши в `.scratch/<feature-slug>/decomposition/hierarchy.md`.

Ключевое: контейнер = `(+)`; каждый уровень содержит только непосредственных потомков; раскрытие «до полного раскрытия»; отображаемые элементы именуются через «Отображение …»; роли делятся только при отличии ≥ 70 %, иначе «Дельта для роли». Формат — табуляция + дефисы (число дефисов = глубина).

### 2. Дополнить (только если дерево уже есть)

Если `hierarchy.md` существует и добавлен новый источник — запусти режим «Дополнение» (`references/inputs-and-augmentation.md`): найди, чего не хватало и теперь можно выделить, добавь только это, ничего не переименовывая и не удаляя без подтверждения. Отчёт и журнал — в `provenance.md`.

### 3. Сгенерировать XML-схему draw.io

По `references/xml-schema-drawio.md` построй `hierarchy.drawio`: `mxGraphModel`, swimlane на каждый контейнер `(+)`, внутри — каркас start → gateway → tasks → gateway → end. На выходе — **только XML**, без Markdown и пояснений. Пройди чек-лист перед выдачей.

### 4. Расставить блоки

По `references/layout.md` расставь swimlane без наложений: дети чётной глубины — вправо, нечётной — вниз, сдвиг соседей — по bbox поддерева. Меняются только координаты.

### 5. Построить матрицу покрытия

По `references/coverage-matrix.md` собери `matrix.xlsx`: «лесенка» по столбцам = глубине, вертикальный merge родителя, контейнеры чёрные, листья синие. Пройди чек-лист.

## Незыблемые правила

- Дерево — единственный источник истины для всех производных артефактов. Ничто не добавляет, не удаляет, не переименовывает, не объединяет, не разбивает и не переставляет элементы дерева.
- На этапах 3–5 документацию не анализируй и не декомпозируй — работай только от готовой иерархии.
- Исключения из декомпозиции (валидации, ошибки, API/backend, SQL, алгоритмы, события, сценарии, тест-кейсы) соблюдаются всегда — см. `references/hierarchy-canon.md`.
- Исходные файлы не перезаписываются. Артефакты сохраняются в `.scratch/<feature-slug>/decomposition/`.
- Каждый этап заканчивается чек-листом. Если канон нарушен — остановись и сообщи, что именно не так, вместо «додумывания».

## Раскладка артефактов

```
.scratch/<feature-slug>/
  decomposition/
    hierarchy.md      # каноническое дерево (источник истины)
    hierarchy.drawio  # XML-схема после расстановки
    matrix.xlsx       # матрица покрытия
    provenance.md     # провенанс узлов + журнал «Дополнения»
    sources/          # снимки входных источников
```
